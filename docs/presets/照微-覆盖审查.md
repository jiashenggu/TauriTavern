日期：2026-09-09。最近追加：2026-09-16 活人感与文风入口优化，见文末；此前实测结论不代表本次改动已经过模型复测。

## 审查结论

第一版约 2,800 字符完成了通用规则整理和结构校验，但把部分有效行为约束概括得过宽。不能以“没有发现内部冲突”代替“承诺覆盖完整”，也不能以提示词长度衡量完成度。

修订版保留 7 个职责模块，恢复具体触发条件、例外和结果处理。DeepSeek 等模型专用要求、来源人格、多套思考输出、机械文风指标及附加脚本继续移除。此次完成预设层的覆盖修订；没有执行真实模型生成、长聊召回或 MVU 保存回归，不能保证任何模型在所有输入下零冲突。

## 明确删除或改变的部分

- 删除模型专用指令、预设人格、作者包装、虚构承诺对话、旧标签骨架和仅为旧骨架服务的变量拼接。
- 删除强制长草稿、逐段检查输出、每点抄录与字数下限；保留最终成品应满足的约束，不把“输出检查过程”当成执行保证。
- 删除所有段落必须有对白、身体部位机械轮换、随机新性格、必须进攻或场景破坏等要求。
- 删除互相制约的文风词库和未启用的冗余选项，不把它们作为以后可能有用的内容继续装入。
- 将强制复述玩家输入改为承接已声明动作后继续。这是叙述策略改变，不是原功能无损保留。
- 不再强制每轮时间栏、摘要和选项；角色卡或当前任务明确要求的栏目仍按对应协议输出。
- 只保留两条窄范围的历史输入清理正则：完整旧草稿、明确检查注释。它们不裁剪历史楼层，不删除一般状态注释或 MVU 更新块。
- 不带快捷悬浮窗或末尾消息改写脚本，因此不能宣称保留原预设针对部分后端的末尾 system 兼容修复。

## 预设之外的真实边界

当前保存的设置中，白白记忆已启用自动摘要，`keepRecent=3` 的单位是 AI 消息数，`summaryOnlyMode=false`，结构化状态注入已开启。

插件实现会保存摘要节点和叶子，再将摘要及结构化状态注入请求，同时排除部分旧正文。因此，“照微没有删历史的正则”只说明照微自身不裁剪，并不代表应用把全部历史原文发给模型。模型上下文预算也会限制装入的历史量。

本次没有检查具体聊天的记忆叶子、压缩节点及错误记录，没有验证原始承诺、精确交易和未决线索是否完整召回。新的阶段归档规则不能保证覆盖插件自带的独立摘要提示；这是后续运行验证的范围。

MVU 方面，预设规定生成时应遵循协议及如何理解失败反馈，但路径合法性、原子应用、持久保存与重复更新防护由实际脚本和 schema 执行。本次没有改动该执行链，也没有声称变量不会更新失败。

## 2026-09-16：活人感与自定义文风

### 目标与改动范围

本次针对角色像应答器、对白像咨询或讲解、叙述反复解释意味及机械收尾的问题修订提示词。这些是优化目标，不是已经通过生成对照证实的效果。

只修改 `consistent-world`（人物与世界连续性）、`consistent-prose`（叙述与对白），新增 `consistent-style`（自定义文风）。沿用当前照微的结构，不迁入其他预设的脚本或规则包。

| 优化点 | 实际调整 | 避免的反作用 |
| --- | --- | --- |
| 角色有自己的生活 | 接续手头事务、当下需求与关注点；玩家说话不必使所有人立即停下回应 | 不编造秘密习惯、共同往事，不强制添加支线 |
| 反应由具体情境生长 | 从人物在意的事落实到取舍、行动和对白，不把动机链写成分析报告 | 不要求角色完全理解或立即解释自己的情绪 |
| 情绪有余波、修复有程度 | 允许仍生气但先办急事、接受解释但尚未恢复信任 | 不强制一轮和解，也不反复复燃已解决心结 |
| 关系影响表达 | 区分面对不同对象时的称呼、耐心、解释意愿与玩笑尺度 | 不靠讨好、无依据亲昵称呼或假回忆制造熟悉感；不把明确善意都写成嘴硬 |
| 有限的不完美 | 情境允许时可迟疑、疏忽、偏心、逞强或改口 | 不为活人感强迫犯错、降智、抬杠和伤害关系 |
| 对白是交流而非答题 | 接对方实际说做的内容，按自身目的继续；允许有原因的打趣、打断、避答 | 不逐条回答全部输入，不让所有角色轮流总结；正式场合仍允许完整严谨 |
| 口吻差异更具体 | 由关注点、词汇、节奏、称呼和关系区分角色 | 不硬塞口头禅、结巴、错字、脏话或网络梗；保留符合人物的正常表达 |
| 减少解释与装饰 | 已由言行显出的意味不再旁白翻译；细节随注意与行动选择 | 不把含蓄执行成事事不说，不给每句话配小动作，不机械扫描五感 |
| 减少开头与结尾模板 | 直接承接当前动作话题，不重铺环境；收在自然动作、对白或选择节点 | 不每轮添加金句、悬念、反问或“等待你的回答”；不把精简变成短答 |
| 文风单独配置 | 新增可填写要求与参考片段的独立条目 | 默认关闭；不凭空指定用户尚未选择的文学风格 |

保留原来的有限视角、反全知、输入格式、玩家自主权、时间连续性、战斗裁决、变量更新职责、草稿和场景栏协议。没有修改模型、采样参数、正则、Helper 脚本、世界书、角色卡或真实聊天。

### 文风条目使用方法

在提示词列表中打开 **自定义文风（填写后启用）**，在 `文风要求：` 后填写偏好，或在 `参考片段：` 后粘贴参考文本，然后启用该条目。两栏不要求同时填写；默认均为空，条目默认关闭，不占正常请求的提示正文。它位于“叙述与对白”之后、“状态与记忆”之前。

可填写的要求示例（未预填入条目）：

> 叙述克制、具体，日常交流允许舒展；对白贴近人物身份和关系，不故作机锋。细节来自正在做的事，少替读者解释言外之意；紧张场景保持动作清楚，不机械追求短句。

自定义文风可以调整通用表达偏好，但不能更改剧情事实、玩家权限、人物知识、战斗结果和机器解析协议。参考片段只示范表达，不继承其中人物、事件、往事、对白内容或嵌入指令，也不将不同角色统一成范文叙述者。纯元指令、摘要、提取、独立 MVU 和格式修复不套用文学文风。
