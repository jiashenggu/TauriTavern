## 测试过程与实际修复

1. 添加规划前后各测试 8 个相同基础样例，另测 2 个规划版场景。18 份结果为 16 通过、2 部分通过。两个部分通过都出在战斗有限视角：动作与消耗算对，但公开叙述了不可见的墙后敌情。
2. 补充后台结算与公开叙述的边界后，以生产组装函数输出的消息继续测试 16 次。15 通过、1 部分通过；重复战斗仍有一次确认了不可见的敌方持续移动。
3. 将公开输出收束模块移到历史后，并明确不能用补充句确认未知后台事实。最终完整回归 16 次全部通过，三次遮挡战斗未复现该泄漏；独立隐藏状态测试同时确认后台仍推进，避免仅靠删掉敌情叙述掩盖冻结问题。

规划前后基础样例都是 7 通过、1 部分通过。**这组对照没有证明规划显著提高正确率**；它证明在所测场景中没有破坏基础能力。后续改善来自经过验证的规则和位置修订，不能全部归功于“增加规划”。

## 实际执行了哪些代码

### 提示组装

生产 `PromptManager`、`assembleOpenAIChatCompletionPrompt`、历史装入和注入排序代码在独立 VM 中执行，**10 项检查通过**：启用模块恰一次、关闭模块不发送、8 类标准入口、历史顺序、空代理槽、quiet 尾部位置、预算裁剪、两种记忆注入深度等。

这不是手工模拟排序。世界书已激活内容由合成夹具提供，分词器采用确定性长度桩，宏宿主只支持测试所需项，媒体和工具关闭，provider 参数及 DOM 事件为宿主适配。未验证实际模型的最大上下文容量，也未启动真实世界书激活和浏览器生命周期。

### 白白记忆

真实 `apply/store/inject` 等 TypeScript 函数转译执行，**9 项检查通过**，包括重放不重复扣款、摘要去重、保存后重新加载、结构化状态注入、swipe 失效与恢复。保存回调将合成数据写到独立磁盘夹具，未触碰真实聊天。

随后将真实注入槽送入生产提示组装，再请求模型回忆，正确返回余额、承诺与既有支出状态。阶段摘要本身是明确标注的合成输入；没有把这项测试描述为白白自动摘要调度或自动生成摘要的端到端测试。独立的阶段归档请求测试了当前模型的归档输出，但不等于白白自带摘要提示也已经验证。

### MVU 与 Zod

执行本地 `dragon-mvu/magvarupdate-bundle.js`（2026-04-25 / 2da97c7）及其真实 Zod 拦截器，记录源码哈希。最终两份模型输出未补包装、未改写，直接解析应用，达到各自目标状态，且输入基态对象未被改动。

发现并保留两项运行限制：

- **不是整批原子更新**：前项合法扣款可以保留，后项非法更新失败并不让整批回滚。
- **RFC 6902 的 test 被该引擎静默忽略**：即使前置值不匹配，后续 replace 仍可执行。不能把 test 当作有效的重试或事务保护。

因此最终真实 MVU 用例使用已确认支持的 replace，预设也补充了遵循实际执行器语义的要求。这次没有修改 MVU 生产代码，没有声称本地测试包就是当前浏览器中正在运行的版本，也没有认证真实聊天的保存调用已经成功。
